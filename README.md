# Lesson Platform Backend

레슨 매칭 플랫폼의 핵심 백엔드 서버입니다.

회원, 레슨, 일정, 결제/환불, 리뷰 도메인을 처리하며, 특히 레슨 신청 이후 결제 상태를 확정하고 이후 일정 및 알림 흐름으로 이어지는 중심 역할을 담당합니다.

## 핵심 도메인: 결제

이 프로젝트의 백엔드에서 가장 중요한 도메인은 결제입니다.

Toss Payments 승인 요청을 통해 결제를 확정하고, 결과에 따라 결제 상태와 이력을 저장합니다. 결제는 외부 PG API와 내부 도메인 상태가 함께 얽히는 영역이기 때문에, 단순 성공 처리보다 실패와 불명확한 상태를 어떻게 다룰지가 중요합니다.

## 결제 흐름

```text
레슨 신청
-> 결제 체크아웃 요청
-> 클라이언트에서 Toss 결제 진행
-> 백엔드에서 Toss 결제 승인 API 호출
-> 승인 결과에 따라 결제 상태 저장
-> 일정 상태 변경 및 알림 이벤트 흐름으로 연결
```

## 중점적으로 고민한 부분

- 외부 PG API 호출 실패나 타임아웃 상황에서 결제 결과를 어떻게 판단할 것인가
- 결제 성공, 실패, 불명확 상태를 어떻게 분리해 저장할 것인가
- Toss 승인 성공 이후 내부 DB 저장에 실패하면 어떤 상태로 남기고 어떻게 추적할 것인가
- 결제 상태와 결제 이력을 분리해 이후 운영자 확인과 재처리 근거를 남길 수 있는가
- 결제 완료 이후 일정 변경과 알림 발송으로 이어지는 흐름을 어떻게 설명할 것인가

## 포트폴리오에서 강조할 점

이 백엔드는 단순히 결제 API를 호출하는 것에서 끝나지 않고, 외부 결제 시스템과 내부 도메인 상태 사이의 불일치 가능성을 고려합니다.

면접이나 코드 리뷰에서는 다음 질문에 답할 수 있도록 정리하는 것이 목표입니다.

- 결제 승인 요청은 어디에서 시작되고 어디에서 상태가 확정되는가
- 결제 실패와 불명확 상태는 어떻게 구분되는가
- 같은 결제 승인 요청이 중복으로 들어오면 어떻게 방어할 것인가
- 결제 성공 이후 일정과 알림 흐름은 어떻게 이어지는가
- 결제 이력은 왜 필요한가
